# Second review regression checks

The launcher checks vary only launcher identity. Use both an exact protected name (`steam.exe`) and a wildcard name (`RooFixtureLauncher.exe`), with an updater and a web helper as positive controls. Run Lower, Placement, Game priority and Background limits with the same fixtures. Inspect each preview's exclusion reason, every fixture's CPU/I/O/memory/affinity readback, and a child started by each launcher after Apply. Restore must recover the positive controls. Keep the installed profile's launcher protections when limiting the fixture profile to owned processes.

The restore-slot check varies only whether a recovery pointer is pending. After Lower Apply, switching presets must leave Review available and Apply disabled with “Restore the last change first”. A direct call to the app service must refuse the second Apply before launching PowerShell or changing the generation, pointer, backup or processes. Restore, then Placement Apply, must work.

The memory-reader check grants a fixture only `PROCESS_QUERY_LIMITED_INFORMATION | SYNCHRONIZE`. Classification must read memory priority without requesting all-access; deny set-information and all-access as negative controls. The fixture owner holds its original handle only for cleanup and independent readback.

The GPU read on the test PC refuses `0x1000` and `0x400`, but accepts `0x600`; GPU writes accept `0x200`. Keep the bulk read limited and permit the additional GPU-read rights only for a requested GPU field. The `gpu-controls` journey requests BelowNormal GPU priority for the same updater/web-helper fixtures through Lower, Game priority and Background limits, verifies their independent GPU values, and restores the originals. Protected processes and launchers must remain unchanged. A limited bulk read must remain unavailable while the explicit-control read succeeds; do not infer that a successful native write also permits a limited readback.

The release-version parser can fail on a missing/truncated DOS or PE header, a wrong optional-header format, an unmapped RVA, resource-directory cycles or offsets outside the resource, malformed version blocks, text length measured as bytes instead of UTF-16 words, alignment errors, a missing StringFileInfo ProductVersion, conflicting translations, or Inno's trailing spaces. Bound every offset and recursion, require an unambiguous ProductVersion, and trim only trailing spaces. The decisive release check uses the real installer with its actual version and then changes only `--version` to a wrong value; neither command contacts a network.

OTA checks vary timer-state readability, download transport/timeout, successful pending-install recovery, and settings-file writability separately. Preserve timer data and settings bytes before faults and restore them afterward. A successful timer read of true still blocks installation; a read failure is logged and permits confirmation. A transport error or the real 20-minute manual download timeout must end with a download-error status, while wrong signed size/hash still ends with the mismatch status. Successful recovery deletes only the installed version folder and keeps the three newest install logs. A read-only settings file must leave the previous toggle value and the app alive. A held SettingsStore with known values must retain all those values if its reload fails.

Every scenario saves raw JSON and rendered UI screenshots. Process checks do not infer success from a backend status: read CPU, I/O, memory and affinity independently. These checks ignore unrelated process CPU usage, working-set size, page-cache memory and unrelated app settings, except for byte-preservation checks during settings faults.
